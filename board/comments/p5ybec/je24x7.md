Ruling: comment files become the 0.1 default. Inline stays permitted but
a board must opt in with `comments: inline`, and consumers read both.

Commenting is the one operation expected to be both concurrent and
semantically independent. Two agents moving an issue to different
columns disagree, and a rename conflict is the correct outcome. Two
agents commenting do not disagree, yet the measured result is silent
loss or a conflict that misleads the resolver. A specification whose
first section claims the filesystem is the record cannot ship a default
write path that drops a reviewer's verdict without a signal.

The strongest objection is that one file read gets the whole issue,
while sidecar costs N+1 reads. That objection counts tool calls rather
than bytes. With the shell the format already assumes, the whole issue
is `cat issues/*/*-<id>.md comments/<id>/*.md`: same content in context,
plus about four lines of frontmatter per comment. Bounded and visible,
against an unbounded and invisible cost on the other side.

Every hybrid examined failed. Inline-canonical with periodic compaction
makes compaction itself a read-modify-write, so two compactions collapse
the same way. A generated inline mirror needs a tool, which breaks the
no-tool claim. Un-collapsible inline text does not exist, because git
refines a conflict by diffing the two sides against each other, so any
shared line is factored out even inside a fence.

Deferred to 0.2: timestamp-prefixed comment filenames so glob order is
chronological, optional `reply_to` for threading, and whether an issue
in a complete column may be compacted to inline for archival.
